# Система организаций - Воркфлоу и архитектура

## Обзор системы

Система организаций в MJ Task Management обеспечивает многоуровневую изоляцию данных и управление доступом на уровне организаций. Каждая организация представляет собой изолированное пространство для управления проектами и задачами.

## Архитектура системы

### Основные компоненты

1. **Organizations** - плоская структура организаций без вложенности
2. **Organization Users** - связь пользователей с организациями с определением ролей
3. **Organization-scoped Projects** - проекты привязанные к организациям
4. **Role-based Access Control** - система ролей и прав доступа

### Структура данных

```
User (1) ←→ (M) OrganizationUser (M) ←→ (1) Organization
                     ↓
                   role: [super_user, org_admin, project_manager, member]
                     
Organization (1) ←→ (M) Project (1) ←→ (M) Task
```

## Роли и права доступа

### SuperUser (Суперпользователь)
**Область действия:** Глобальная система

**Права:**
- ✅ Создание/редактирование/удаление организаций
- ✅ Назначение/изменение ролей пользователей в любых организациях
- ✅ Создание других SuperUser'ов
- ✅ Доступ ко всем проектам и задачам системы
- ✅ Управление системными настройками
- ✅ Просмотр аналитики по всем организациям
- ✅ Деактивация/активация организаций
- ✅ Массовые операции (перенос проектов между организациями)

**Ограничения:**
- ⚠️ Не может быть исключен из организации обычными администраторами
- ⚠️ Действия логируются с повышенным приоритетом

**Создание первого SuperUser:**
- Первый зарегистрированный пользователь автоматически становится SuperUser
- Или создается через команду artisan при деплое

### OrgAdmin (Администратор организации)
**Область действия:** Конкретная организация

**Права:**
- ✅ Приглашение пользователей в организацию (создание без пароля)
- ✅ Назначение ролей: ProjectManager, Member
- ✅ Исключение пользователей из организации (кроме SuperUser)
- ✅ Создание/редактирование/удаление проектов в организации
- ✅ Удаление организации (soft delete)
- ✅ Назначение ProjectManager'ов на проекты
- ✅ Просмотр всех проектов и задач в организации
- ✅ Настройка параметров организации
- ✅ Просмотр аналитики по организации

**Ограничения:**
- ❌ Не может управлять другими OrgAdmin в той же организации
- ❌ Не может исключить создателя организации
- ❌ Не может переносить проекты в другие организации
- ❌ Не может видеть данные других организаций

### ProjectManager (Менеджер проектов)
**Область действия:** Назначенные проекты в организации

**Права:**
- ✅ Создание проектов в своей организации
- ✅ Полное управление назначенными проектами
- ✅ Создание/редактирование/удаление задач в своих проектах
- ✅ Назначение участников на задачи из членов организации
- ✅ Приглашение новых Member'ов в организацию
- ✅ Настройка воркфлоу проектов
- ✅ Просмотр отчетов по своим проектам

**Ограничения:**
- ❌ Не может управлять проектами других ProjectManager'ов
- ❌ Не может назначать ProjectManager'ов
- ❌ Не может исключать пользователей из организации
- ❌ Не может назначать на задачи пользователей из других организаций

### Member (Участник)
**Область действия:** Назначенные проекты

**Права:**
- ✅ Просмотр проектов где является участником
- ✅ Создание задач в проектах где участвует
- ✅ Работа с назначенными задачами
- ✅ Комментирование задач в доступных проектах
- ✅ Отслеживание времени по задачам
- ✅ Просмотр статистики по своим задачам

**Ограничения:**
- ❌ Не может создавать проекты
- ❌ Не может приглашать пользователей
- ❌ Не может назначать других участников на задачи
- ❌ Не может видеть проекты где не участвует

## Воркфлоу системы

### 1. Создание организации

#### Вариант A: Создание SuperUser'ом

**Инициатор:** SuperUser

**Процесс:**
1. SuperUser создает новую организацию
2. Заполняет базовую информацию (название, описание, настройки)
3. Назначает первого OrgAdmin из существующих пользователей
4. Организация становится активной

#### Вариант B: Создание при регистрации пользователем

**Инициатор:** Новый пользователь

**Процесс:**
1. Пользователь регистрируется в системе (не по инвайту)
2. Система предлагает создать организацию или присоединиться к существующей
3. При выборе создания:
   - Пользователь заполняет название организации
   - Система создает обычную организацию
   - Пользователь автоматически становится OrgAdmin этой организации
4. При выборе присоединения:
   - Пользователь вводит код приглашения или email администратора
   - Отправляется запрос на присоединение

**Подводные камни:**
- ⚠️ Необходимо сразу назначить OrgAdmin, иначе организация будет неуправляемой
- ⚠️ Имя организации должно быть уникальным
- ⚠️ При создании должны устанавливаться настройки по умолчанию
- ⚠️ Нужно валидировать что пользователь не зарегистрирован по инвайту

### 2. Приглашение пользователей

**Инициатор:** OrgAdmin, ProjectManager (только для роли Member)

**Упрощенный процесс приглашения:**
1. OrgAdmin создает пользователя с email но без пароля
2. Указывает роль (ProjectManager, Member)
3. Пользователь добавляется в организацию
4. При первом входе пользователь устанавливает пароль

**Процесс для существующих пользователей:**
1. Поиск пользователя по email
2. Добавление в организацию с указанной ролью
3. Уведомление пользователю о добавлении

**Подводные камни:**
- ⚠️ Пользователь может состоять в нескольких организациях
- ⚠️ Нужно проверять что пользователь еще не состоит в данной организации
- ⚠️ Нужно логировать все добавления для аудита
- ⚠️ При первом входе проверять есть ли пароль

### 3. Управление ролями

**Смена ролей:**
- SuperUser может назначить любую роль любому пользователю
- OrgAdmin может назначать только роли ProjectManager и Member
- Понижение роли требует подтверждения
- При смене роли пересчитываются права доступа к проектам

**Подводные камни:**
- ⚠️ При понижении ProjectManager до Member нужно переназначить его проекты
- ⚠️ Нельзя оставить организацию без OrgAdmin
- ⚠️ При исключении пользователя нужно переназначить его активные задачи

### 4. Работа с проектами

**Создание проекта:**
1. OrgAdmin или ProjectManager создает проект
2. Проект автоматически привязывается к организации
3. Создатель получает права управления проектом
4. Настраивается команда проекта из членов организации

**Назначение участников:**
- Можно назначать только пользователей из той же организации
- Участники наследуют доступ к задачам проекта
- При исключении из организации пользователь теряет доступ ко всем проектам

**Подводные камни:**
- ⚠️ При переносе пользователя в другую организацию нужно решить судьбу его задач
- ⚠️ Нужно предотвращать ситуацию когда в проекте не остается ни одного менеджера
- ⚠️ При деактивации организации все проекты должны стать недоступными

### 5. Управление задачами

**Создание и назначение:**
- Задачи создаются в рамках проектов
- Назначать можно только участников организации
- Права на задачи наследуются от проектов

**Подводные камни:**
- ⚠️ При исключении исполнителя из организации задачи должны быть переназначены
- ⚠️ Нужно контролировать что наблюдатели и рецензенты также состоят в организации
- ⚠️ История изменений должна сохраняться даже после исключения пользователей

## Сценарии исключений

### Исключение пользователя из организации

**Процесс:**
1. Проверка активных назначений пользователя
2. Переназначение активных задач другим участникам
3. Удаление из всех проектов организации
4. Сохранение истории для аудита
5. Уведомление пользователя об исключении

**Критические проверки:**
- ❌ Нельзя исключить последнего OrgAdmin
- ❌ Нельзя исключить SuperUser
- ❌ Нужно переназначить активные задачи

### Деактивация организации

**Процесс:**
1. Блокировка создания новых проектов/задач
2. Сохранение всех данных для аудита
3. Уведомление всех участников
4. Возможность реактивации в течение grace period

**Восстановление:**
- Данные сохраняются в течение 30 дней
- SuperUser может реактивировать организацию
- При реактивации восстанавливаются все связи

## Технические ограничения

### Производительность
- Индексы на organization_id во всех связанных таблицах
- Кеширование списка организаций пользователя
- Пагинация при больших объемах данных

### Безопасность
- Все операции логируются с указанием организации
- Проверка прав доступа на уровне middleware
- Изоляция данных между организациями

### Масштабируемость
- Возможность шардинга по организациям
- Архивирование неактивных организаций
- Лимиты на количество пользователей в организации

## API Endpoints

### Управление организациями
```
POST   /api/organizations              # Создание (SuperUser или при регистрации)
GET    /api/organizations              # Список доступных орг.
GET    /api/organizations/{id}         # Детали организации
PUT    /api/organizations/{id}         # Редактирование
DELETE /api/organizations/{id}         # Удаление (SuperUser)
```

### Управление участниками
```
POST   /api/organizations/{id}/invite       # Приглашение
GET    /api/organizations/{id}/members      # Список участников
PUT    /api/organizations/{id}/members/{uid} # Изменение роли
DELETE /api/organizations/{id}/members/{uid} # Исключение
```

### Проекты в контексте организации
```
GET    /api/organizations/{id}/projects     # Проекты организации
POST   /api/organizations/{id}/projects     # Создание проекта
```

## Миграция данных

### Этапы внедрения
1. Создание таблиц organizations, organization_user
2. Добавление organization_id в projects
3. Создание дефолтной организации для существующих данных
4. Миграция пользователей в дефолтную организацию
5. Внедрение middleware для проверки прав
6. Обновление процесса регистрации для создания организаций пользователями
7. Обновление UI для работы с организациями

### Обратная совместимость
- Создается организация "Первая организация"
- Существующие проекты привязываются к ней
- Все пользователи получают роль Member в этой организации
- Отдельно создается админ для "Первой организации"
- Новые пользователи при регистрации могут создавать собственные организации

## UI/UX решения

### Переключение организаций
- Селектор организаций в правом верхнем углу при наведении на иконку аккаунта
- Текущая организация сохраняется в localStorage браузера
- При переключении обновляется весь контекст приложения

### Первый вход без пароля
- При входе проверка наличия пароля
- Если пароля нет - редирект на страницу создания пароля
- После создания пароля - обычный вход в систему

## Технические детали

### Удаление организаций
- Soft delete для организаций (deleted_at)
- При удалении все проекты и задачи также soft delete
- Возможность восстановления в течение периода хранения
- Может удалять: SuperUser или OrgAdmin организации

### Хранение контекста
- Текущая организация: localStorage
- Сессионные данные: стандартная сессия Laravel
- Кеш списка организаций пользователя

### Middleware и права доступа
- Один универсальный `OrganizationMiddleware` с параметрами ролей
- Проверка принадлежности к организации на уровне middleware
- Дополнительные scopes в моделях для фильтрации данных по организации
- Примеры использования:
  ```php
  Route::middleware(['organization:org_admin,super_user'])->group(...);
  Route::middleware(['organization:member'])->group(...);
  ```

## Мониторинг и аналитика

### Ключевые метрики
- Количество активных организаций
- Распределение пользователей по ролям
- Активность в рамках организаций
- Производительность изоляции данных

### Алерты
- Организация без администратора
- Подозрительная активность между организациями
