# ✅ ЧЕК-ЛИСТ ПРАВИЛ РАЗРАБОТКИ

> **ВАЖНО**: При каждом создании файла/функции ОБЯЗАТЕЛЬНО проверяй по этому чек-листу!

---

## 🎯 **ПРИНЦИП ЕДИНСТВЕННОЙ ОТВЕТСТВЕННОСТИ (SRP)**

### ✅ Перед написанием функции/composable:
- [ ] **Одна функция = одна задача**
- [ ] **Если функция больше 20 строк - РАЗБЕЙ на части**
- [ ] **Если composable возвращает больше 5 вещей - РАЗБЕЙ на части**

### ❌ Плохо:
```javascript
// Делает всё сразу
const { loading, getTask, getTasks, createTask, showNotification } = useEverything()
```

### ✅ Хорошо:
```javascript
// Каждый composable имеет свою ответственность
const { getTasks } = useTasks()           // только API
const { showNotification } = useNotifications()  // только уведомления
const { loading } = useTasksList()       // только состояние списка
```

---

## 🏗️ **РАЗДЕЛЕНИЕ СОСТОЯНИЙ**

### ✅ Для каждого UI компонента:
- [ ] **Отдельное состояние loading**
- [ ] **Изолированные данные**
- [ ] **Никаких общих состояний между разными компонентами**

### ❌ Плохо:
```javascript
const loading = ref(false)  // общий для всего
```

### ✅ Хорошо:
```javascript
const tasksLoading = ref(false)    // только для списка
const modalLoading = ref(false)    // только для модалки
const createLoading = ref(false)   // только для создания
```

---

## 📁 **СЛОИСТАЯ АРХИТЕКТУРА**

### ✅ Строгое разделение по слоям:
- [ ] **API слой** (`composables/api/`) - только вызовы API
- [ ] **UI слой** (`composables/ui/`) - только UI логика (модалки, уведомления)
- [ ] **Features слой** (`composables/features/`) - бизнес-логика
- [ ] **Utils слой** (`utils/`) - вспомогательные функции

### ❌ Нельзя:
- API логику в UI composables
- Бизнес-логику в API composables
- UI логику в Features composables

---

## 🔗 **ИНВЕРСИЯ ЗАВИСИМОСТЕЙ**

### ✅ Завись от абстракций:
- [ ] **Компоненты зависят от composables, а не от конкретных API**
- [ ] **Явные импорты, никакой магии**

### ❌ Плохо:
```javascript
// Компонент напрямую зависит от API
const response = await fetch('/api/tasks')
```

### ✅ Хорошо:
```javascript
// Компонент зависит от абстракции
const { getTasks } = useTasks()
const tasks = await getTasks()
```

---

## 💎 **ЯВНОЕ ЛУЧШЕ НЕЯВНОГО**

### ✅ Все действия должны быть понятными:
- [ ] **Явные вызовы обновления списка**
- [ ] **Понятные названия функций**
- [ ] **Никаких скрытых побочных эффектов**

### ❌ Плохо:
```javascript
const updateTask = async (data) => {
  await api.updateTask(data)
  // магическое обновление списка где-то внутри
}
```

### ✅ Хорошо:
```javascript
const updateTask = async (data) => {
  await api.updateTask(data)
  await refreshTasksList() // явно обновляем список
}
```

---

## ⚡ **FAIL FAST**

### ✅ Ошибки должны проявляться рано:
- [ ] **Валидация параметров в начале функции**
- [ ] **Выброс ошибок при неверных данных**

### ✅ Пример:
```javascript
export function useTask(taskId) {
  if (!taskId) {
    throw new Error('taskId обязателен')
  }
  // остальная логика
}
```

---

## 🧩 **КОМПОЗИЦИЯ vs НАСЛЕДОВАНИЕ**

### ✅ Строй сложную логику из простых блоков:
- [ ] **Базовые composables для переиспользования**
- [ ] **Специфичные composables расширяют базовые**

### ✅ Пример:
```javascript
// Базовый
export function useModal() {
  const isOpen = ref(false)
  return { isOpen, open, close }
}

// Специфичный
export function useTaskModal() {
  const modal = useModal()  // композиция
  const task = ref(null)
  return { ...modal, task }
}
```
